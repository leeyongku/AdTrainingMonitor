# 메인 화면(MainActivity) 구성 상세 설명

`app/src/main/java/com/training/monitor/ui/main/MainActivity.kt`

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 역할 | 로그인 성공 직후 진입하는 "메인 컨테이너" 화면. 화면 자체는 상단 툴바 + 하단 네비게이션 + Fragment 컨테이너로 된 빈 껍데기이고, 실제 탭별 화면은 로그인한 사용자의 **역할(role)**에 따라 완전히 다른 구성으로 채워진다. |
| 상위 클래스 | `androidx.appcompat.app.AppCompatActivity` |
| 아키텍처 패턴 | MVVM. `MainActivity`는 `NavController`/`BottomNavigationView`/`Toolbar` 같은 View 객체를 다루는 역할만 하고, 역할 판별(`isAdmin`)과 로그아웃은 [MainViewModel](#3-mainviewmodel과의-관계)이 담당한다. |
| 연결된 레이아웃 | `res/layout/activity_main.xml` → ViewBinding으로 `ActivityMainBinding` 자동 생성 |
| 진입 경로 | [LoginActivity](./LoginActivity-클래스-설명.md)가 로그인 성공 시(또는 이미 로그인된 상태로 앱을 열었을 때) 시작한다. 단, `TokenManager.mustChangePassword`가 true인 계정은 이 화면 대신 `ChangePasswordActivity`(강제 모드)를 먼저 거친다. |
| 종료 경로 | 툴바의 "로그아웃" 액션 → `LoginActivity`로 이동하며 `finish()` (뒤로가기로 못 돌아오게 함). |

**이 화면의 핵심 아이디어**: `MainActivity` 자기 자신은 "관리자 화면"인지 "대원 화면"인지 전혀 모른다. `onCreate()`에서 딱 한 번 `viewModel.isAdmin` 값을 읽어, 그 값에 따라 **네비게이션 그래프 리소스**와 **메뉴 리소스**를 다르게 선택해서 끼워 넣을 뿐이다. 그 뒤로는 안드로이드의 `NavController`/`BottomNavigationView` 표준 연결(`setupWithNavController`)이 탭 전환을 전부 처리한다.

---

## 2. 레이아웃 구조 (`activity_main.xml`)

```
CoordinatorLayout (전체 화면)
├─ AppBarLayout
│   └─ Toolbar (id=toolbar)              — 상단 바. 제목 "훈련 모니터링" 고정, 우측에 역할별 액션 메뉴
└─ LinearLayout (세로, toolbar 아래 전체를 채움)
    ├─ FragmentContainerView (id=nav_host_fragment, weight=1)
    │     → NavHostFragment가 자동으로 붙는 자리. 실제 탭 화면(Fragment)들이 여기에 교체되며 그려진다.
    └─ BottomNavigationView (id=bottomNav)  — 하단 탭 바. 역할별 메뉴 리소스로 채워짐
```

`FragmentContainerView`에 `android:name="androidx.navigation.fragment.NavHostFragment"`가 XML에 이미 박혀있기 때문에, `MainActivity`는 이 컨테이너를 직접 만들 필요 없이 `supportFragmentManager.findFragmentById(R.id.nav_host_fragment)`로 찾기만 하면 된다.

## 3. `MainViewModel`과의 관계

파일: `app/src/main/java/com/training/monitor/ui/main/MainViewModel.kt`

```kotlin
class MainViewModel(application: Application) : AndroidViewModel(application) {
    private val tokenManager = TokenManager(application)

    val isAdmin: Boolean get() = tokenManager.isAdmin

    fun logout() {
        tokenManager.clear()
    }
}
```

| 멤버 | 설명 |
|---|---|
| `isAdmin` | `TokenManager.role == "ADMIN"` 여부. `MainActivity.onCreate()`가 이 값 하나로 네비게이션 그래프/하단 메뉴/툴바 메뉴 세 가지를 전부 분기한다. |
| `logout()` | 저장된 토큰(`accessToken`/`refreshToken`/`role`/`mustChangePassword`)을 전부 삭제한다. 서버의 `/api/auth/logout`(refresh token 폐기)은 호출하지 않는다 — 로컬 토큰만 지우는 가벼운 방식이며, 이 프로젝트의 기존 동작을 그대로 유지한 것이다. 화면 전환(`LoginActivity`로 이동)은 Activity가 담당한다. |

다른 화면의 ViewModel들과 달리 `MainViewModel`은 네트워크 호출이나 로딩 상태가 없는 "껍데기" ViewModel이라 `LiveData`가 하나도 없다 — `TokenManager`를 직접 들고 있던 책임(역할 판별, 로그아웃 시 토큰 삭제)만 Activity에서 떼어내 옮겨둔 것이다.

## 4. 역할에 따라 완전히 달라지는 3가지 리소스

`onCreate()` 한 곳에서 `viewModel.isAdmin` 값으로 아래 세 리소스를 동시에 고른다.

| 구분 | 관리자(ADMIN) | 대원(MEMBER) |
|---|---|---|
| **네비게이션 그래프** | `res/navigation/nav_admin.xml` | `res/navigation/nav_member.xml` |
| **하단 탭 메뉴** | `res/menu/menu_admin.xml` | `res/menu/menu_member.xml` |
| **툴바 우측 메뉴** | `res/menu/menu_toolbar.xml` | `res/menu/menu_toolbar_member.xml` |

### 4-1. 관리자 (`nav_admin.xml` + `menu_admin.xml`)

시작 화면(`startDestination`)은 **대원 관리**다.

| 탭 순서 | id | 아이콘 | 라벨 | 연결된 Fragment |
|---|---|---|---|---|
| 1 (시작) | `memberListFragment` | `ic_menu_manage` | 대원 관리 | `ui.member.MemberListFragment` |
| 2 | `recordInputFragment` | `ic_menu_edit` | 기록 입력 | `ui.record.RecordInputFragment` |
| 3 | `statsFragment` | `ic_menu_compass` | 통계 | `ui.stats.StatsFragment` |

### 4-2. 대원 (`nav_member.xml` + `menu_member.xml`)

탭이 하나뿐이라 사실상 하단 네비게이션은 장식에 가깝다.

| 탭 순서 | id | 아이콘 | 라벨 | 연결된 Fragment |
|---|---|---|---|---|
| 1 (시작) | `myRecordFragment` | `ic_menu_recent_history` | 내 기록 | `ui.record.MyRecordFragment` |

> `menu_*.xml`의 `<item android:id>`는 **반드시** `nav_*.xml`의 `<fragment android:id>`와 이름이 같아야 한다. `setupWithNavController()`가 이 id를 기준으로 "탭 클릭 → 해당 목적지로 이동"을 자동 연결하기 때문이다 (이름이 다르면 탭을 눌러도 화면이 안 바뀐다).

### 4-3. 툴바 우측 메뉴 (`menu_toolbar.xml` vs `menu_toolbar_member.xml`)

| id | 아이콘 | 라벨 | 관리자 | 대원 |
|---|---|---|:---:|:---:|
| `actionChangePassword` | `ic_menu_edit` | 비밀번호 변경 | ✗ | ✓ |
| `actionLogout` | `ic_lock_power_off` | 로그아웃 | ✓ | ✓ |

관리자용 `menu_toolbar.xml`에는 "로그아웃"만 있다. 관리자 본인의 비밀번호를 관리자 스스로 바꾸는 화면이 아직 없어서(별도 관리 화면 부재) 이번 범위에서는 대원에게만 노출한다.

## 5. `onCreate()` 동작 순서

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    binding = ActivityMainBinding.inflate(layoutInflater)
    setContentView(binding.root)

    // 1) NavHostFragment를 찾아 NavController를 꺼낸다
    val navHost = supportFragmentManager.findFragmentById(R.id.nav_host_fragment) as NavHostFragment
    val navController = navHost.navController

    // 2) 역할에 따라 네비게이션 그래프 + 하단 메뉴 리소스를 고른다
    val navGraph = if (viewModel.isAdmin)
        navController.navInflater.inflate(R.navigation.nav_admin)
    else
        navController.navInflater.inflate(R.navigation.nav_member)
    navController.graph = navGraph

    // 3) 하단 네비게이션에 메뉴를 채우고, 탭 클릭 시 자동으로 목적지 전환되도록 연결
    binding.bottomNav.inflateMenu(menuRes)
    binding.bottomNav.setupWithNavController(navController)

    // 4) 툴바 우측 메뉴도 역할별로 채우고 클릭을 분기 처리
    binding.toolbar.inflateMenu(if (viewModel.isAdmin) R.menu.menu_toolbar else R.menu.menu_toolbar_member)
    binding.toolbar.setOnMenuItemClickListener { item -> ... }
}
```

| 단계 | 코드 | 설명 |
|---|---|---|
| 1 | `supportFragmentManager.findFragmentById(...) as NavHostFragment` | XML에 미리 박아둔 `NavHostFragment`를 코드에서 찾아, 화면 전환을 제어하는 `NavController`를 얻는다. |
| 2 | `navController.navInflater.inflate(R.navigation.nav_admin 또는 nav_member)` | 네비게이션 그래프 XML을 런타임에 파싱해 `NavGraph` 객체로 만든다. `navController.graph = navGraph`로 실제 적용한다. |
| 3 | `bottomNav.inflateMenu(...)` + `setupWithNavController(navController)` | 하단 탭 버튼들을 메뉴 리소스로 채우고, 안드로이드 Navigation 컴포넌트의 표준 헬퍼로 "탭 클릭 → 목적지 이동"을 자동 연결한다 (직접 리스너를 달지 않아도 됨). |
| 4 | `toolbar.inflateMenu(...)` + `setOnMenuItemClickListener { ... }` | 툴바 우측 액션 아이콘을 채우고, 클릭된 항목의 id로 분기해 "비밀번호 변경 화면 열기" 또는 "로그아웃" 동작을 실행한다. |

## 7. 설계 메모

- **"하나의 Activity, 두 개의 그래프" 패턴**: 관리자/대원용으로 `MainActivity`를 두 개 만드는 대신, 하나의 Activity가 역할에 맞는 네비게이션 그래프·메뉴 리소스를 골라 끼우는 방식을 쓴다. 툴바·하단 네비게이션 같은 공통 뼈대 코드를 중복 없이 재사용할 수 있다는 장점이 있다.
- **역할 판별은 `onCreate()`에서 딱 한 번만**: 로그인 중 역할이 바뀌는 일은 없으므로(로그아웃 후 재로그인해야 역할이 바뀔 수 있음), `isAdmin`을 매번 다시 읽지 않고 화면 진입 시점에 한 번만 분기한다. 역할이 바뀌려면 결국 `MainActivity`를 새로 시작해야 하므로(로그아웃 → 재로그인 → `LoginActivity`가 새 `MainActivity` 시작) 이 설계로 충분하다.
- **`menu_*.xml`의 id와 `nav_*.xml`의 id 일치가 생명**: 새 탭을 추가할 때 이 두 파일의 id를 다르게 적으면 컴파일은 되지만 탭이 눌리지 않는 조용한 버그가 된다. 새 탭을 추가할 때는 항상 두 파일을 함께 수정해야 한다.
- **관리자는 왜 "비밀번호 변경"이 없는가**: 이번 범위(대원의 임시 비밀번호 강제/자율 변경)에서 관리자 계정 자체를 관리하는 화면을 별도로 만들지 않았기 때문이다. 백엔드 API(`PATCH /api/auth/password`)는 역할 구분 없이 이미 동작하므로, 필요해지면 `menu_toolbar.xml`에 같은 `actionChangePassword` 항목만 추가하면 된다(코드 분기는 이미 `MainActivity`에 준비돼 있다).
